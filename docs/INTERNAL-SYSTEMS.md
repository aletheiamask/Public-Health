## 1. แนวคิด: "เข้าเว็บเดียว ทำงานได้ทั้งวัน"

ทุกวันนี้เจ้าหน้าที่ต้องสลับไปมาระหว่างเว็บข่าว, ระบบสารบรรณ, กระดาษใบลา, สมุดจองห้อง, กลุ่ม LINE, Google Drive และไฟล์ Excel ส่งรายงาน เป้าหมายคือรวมงานประจำวันไว้ในเว็บแอปเดียว:

1. **หน้า "งานของฉัน" หน้าเดียว** — ทุกอย่างที่รอฉันอยู่ (รับทราบ, อนุมัติ, หนังสือเข้า, งานที่ได้รับมอบหมาย, ประชุมวันนี้) ไม่ต้องไล่เปิดทีละระบบ
2. **ขอ–อนุมัติ–ติดตาม ในที่เดียว** — แบบฟอร์มทุกชนิด (ลา, ไปราชการ, จองรถ, ขอซื้อ) ใช้ **เครื่องมืออนุมัติกลางตัวเดียว** หน้าตาเหมือนกัน เรียนรู้ครั้งเดียวใช้ได้หมด
3. **ไม่ต้องพิมพ์กระดาษ** — ระบบออกเอกสาร PDF ตามรูปแบบหนังสือราชการ (ฟอนต์ TH Sarabun) พร้อมลงนามอิเล็กทรอนิกส์
4. **ใช้บนมือถือได้ทุกระบบ** — ผู้บริหารอนุมัติได้จากมือถือ, เจ้าหน้าที่ รพ.สต. ยื่นใบลาได้โดยไม่ต้องเข้าอำเภอ
5. **ทุกวัยใช้ได้** — ใช้ Design System เดียวกับฝั่งข่าว (ตัวอักษร 18px, ปุ่มใหญ่, ภาษาง่าย)

## 2. ผลการสำรวจ

### 2.1 ระบบที่หน่วยงานรัฐไทยใช้กันทั่วไป (e-Office)
จากคู่มือ e-Office ของหน่วยงานภาครัฐ/มหาวิทยาลัย และงานวิจัยการใช้สารบรรณอิเล็กทรอนิกส์ในโรงพยาบาลสังกัด สธ. พบชุดระบบที่ใช้ซ้ำๆ คือ
**สารบรรณอิเล็กทรอนิกส์ (e-Saraban), ระบบลา, จองห้องประชุม, จองรถ, แจ้งเรื่อง/แจ้งซ่อม, e-Meeting และลงนามอิเล็กทรอนิกส์** — ประโยชน์หลักที่รายงานคือลดความล่าช้าในการเดินหนังสือ และลดกระดาษ

### 2.2 แนวโน้ม Digital Workplace / Intranet สากล (2025–2026)
- พื้นที่ทำงานเป็นทีม (team workspace), เวิร์กโฟลว์ และการมีส่วนร่วม (โพล, กระดานถาม-ตอบ) สำคัญกว่าการเป็นแค่ที่เก็บเอกสาร
- **ค้นหาเก่ง** และ **ปรับเนื้อหาตามบทบาท/หน่วยงาน** เป็นพื้นฐาน
- **ใช้บนมือถือได้** สำหรับคนหน้างาน (เทียบกับเจ้าหน้าที่ รพ.สต.)
- **เชื่อมกับระบบอื่น** (HR, IT support, ปฏิทิน)
- ผู้ช่วย AI สำหรับค้นหา/สรุปเอกสาร — แต่ต้องมีธรรมาภิบาลข้อมูล

### 2.3 ข้อเฉพาะของหน่วยงานสาธารณสุขไทยที่ต้องรองรับ
| เรื่อง | ผลต่อการออกแบบ |
|---|---|
| **ระเบียบงานสารบรรณ** (ระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ และฉบับแก้ไขที่รองรับระบบสารบรรณอิเล็กทรอนิกส์) | ทะเบียนรับ-ส่ง, ชั้นความเร็ว (ด่วนที่สุด/ด่วนมาก/ด่วน), ชั้นความลับ, รูปแบบหนังสือ 6 ชนิด, การเกษียนหนังสือ |
| **พ.ร.บ.ว่าด้วยธุรกรรมทางอิเล็กทรอนิกส์** | ลงนามอิเล็กทรอนิกส์มีผลทางกฎหมาย — ต้องเก็บหลักฐานการลงนาม |
| **ระเบียบว่าด้วยการลาของข้าราชการ** และสิทธิ์ลาที่ต่างกันตามประเภทบุคลากร (ข้าราชการ, พนักงานราชการ, พนักงานกระทรวงสาธารณสุข, ลูกจ้าง) | กฎการลาเป็น **ข้อมูลตั้งค่าได้** ไม่ฝังในโค้ด |
| **ปีงบประมาณ** ต.ค.–ก.ย. | รายงาน, วันลาสะสม, งบประมาณ ใช้ปีงบประมาณเป็นหลัก |
| **การรักษาราชการแทน / มอบอำนาจ** | ผู้อนุมัติไม่อยู่ → อนุมัติแทนได้ตามคำสั่ง (มีวันเริ่ม-สิ้นสุด) |
| **PDPA** + ข้อมูลสุขภาพ (ใบรับรองแพทย์ในใบลาป่วย) | ไฟล์แนบอ่อนไหวเห็นเฉพาะผู้อนุมัติและ HR |
| **ITA** | ระบบจัดซื้อ/โครงการ/รายงาน ช่วยดึงข้อมูลไปเปิดเผยตามเกณฑ์ได้ |

## 4. แกนกลางร่วม (Core Engines) — สร้างครั้งเดียว ใช้ทุกโมดูล

นี่คือส่วนที่ทำให้ระบบ "ครบวงจร" โดยไม่ต้องเขียนซ้ำ และทำให้ทุกระบบหน้าตา/วิธีใช้เหมือนกัน

### 4.1 Workflow & Approval Engine ⭐ (สำคัญที่สุด)
- นิยามสายอนุมัติเป็น **ข้อมูล** (ไม่ฝังโค้ด) เช่น ใบลา: `ผู้ขอ → หัวหน้ากลุ่มงาน → (ถ้า > 10 วัน) นพ.สสจ.`
- ขั้นตอนรองรับ: อนุมัติ, ตีกลับแก้ไข, ไม่อนุมัติ, ส่งต่อ, **ขนาน** (ต้องครบทุกคน) / **ใครคนหนึ่ง**, เงื่อนไขตามค่าในฟอร์ม
- ผู้อนุมัติกำหนดได้ทั้งแบบ "ตำแหน่ง" (หัวหน้าของหน่วยงานผู้ขอ) และ "บุคคล"
- **รักษาราชการแทน/มอบอำนาจ**: ตั้งช่วงวันที่ → งานเข้าไปที่ผู้รักษาราชการแทนอัตโนมัติ บันทึกว่า "อนุมัติแทน"
- SLA และเตือนอัตโนมัติเมื่อค้างนานเกินกำหนด
- ทุกขั้นบันทึกลง audit log และแสดงเป็นไทม์ไลน์ให้ผู้ขอเห็นว่าเรื่องอยู่ที่ใคร

```go
// internal/workflow
type Definition struct {
    Key   string   // "leave", "travel", "vehicle", "purchase_request", ...
    Steps []Step
}
type Step struct {
    Name      string
    Approver  ApproverRule // ByPosition("head_of_requester_org") | ByUser(id) | ByRole(...)
    Mode      Mode         // Any | All
    Condition string       // expr เช่น "form.days > 10" (ใช้ expr-lang/expr)
    SLA       time.Duration
}
```

### 4.2 Form Builder
- **ทยอยทำ**: ระยะ 2 ใช้ฟอร์มที่เขียนในโค้ด (ลา, ไปราชการ, จองรถ) บนแกน workflow ก่อน; Form Builder เต็มรูปแบบมาในระยะ 3 — ลดความเสี่ยงงานใหญ่เกินตั้งแต่ต้น
- Unit Admin สร้างแบบฟอร์มเองได้ (ข้อความ, ตัวเลข, วันที่, เลือก, แนบไฟล์, ตาราง, ลายเซ็น) แล้วผูกกับสายอนุมัติ — ไม่ต้องรอโปรแกรมเมอร์
- ใช้สร้าง: บันทึกข้อความขออนุมัติทั่วไป, แบบขอใช้ข้อมูล, แบบรายงานจากหน่วยบริการ, แบบสำรวจ
- เก็บโครงฟอร์มเป็น JSON Schema + มีเวอร์ชัน (คำตอบเก่าไม่เสียเมื่อแก้ฟอร์ม)

### 4.3 ปฏิทินและการจองทรัพยากร
- เครื่องมือเดียวใช้กับ ห้องประชุม, รถ, อุปกรณ์ (โปรเจกเตอร์, ชุดประชุมออนไลน์)
- ตรวจเวลาชนกันระดับฐานข้อมูล (PostgreSQL exclusion constraint บนช่วงเวลา — จองซ้อนไม่ได้แม้กดพร้อมกัน)
- **ปฏิทินรวมของฉัน**: ลา + ประชุม + ไปราชการ + เวร + จองรถ ในมุมมองเดียว, export/subscribe เป็น iCal ไปมือถือได้

### 4.4 ศูนย์แจ้งเตือน (Notification Center)
- กระดิ่งในเว็บ (อัปเดตทันทีด้วย Server-Sent Events จาก Go), Web Push, อีเมล, (LINE OA เมื่อเปิดใช้)
- ผู้ใช้เลือกได้ว่าเรื่องไหนแจ้งช่องทางไหน และตั้ง "สรุปรายวัน" แทนการแจ้งทีละเรื่อง

### 4.5 เอกสาร PDF & ลงนามอิเล็กทรอนิกส์
- สร้าง PDF ตามแบบหนังสือราชการ (ครุฑ, ส่วนราชการ, ที่, วันที่, เรื่อง, ฟอนต์ TH Sarabun New) จากเทมเพลต
- ลงนาม 2 ระดับ:
  1. **ลายมือชื่ออิเล็กทรอนิกส์ทั่วไป** — ยืนยันตัวตนด้วย Passkey/OTP ณ ขณะลงนาม (step-up), ประทับภาพลายเซ็น, เก็บ hash SHA-256 ของเอกสาร + เวลา + IP เป็นหลักฐานใน audit log แบบ hash chain, ประทับเวลาจากผู้ให้บริการประทับเวลาที่เชื่อถือได้ (RFC 3161) ถ้าใช้ได้ — เอกสารที่ลงนามแล้วแก้ไม่ได้ ต้องออกฉบับใหม่
  2. **ลายมือชื่อดิจิทัล (PAdES)** — ลงนามด้วยใบรับรองของหน่วยงาน ตรวจสอบได้ใน PDF reader (ระยะหลัง)
- ทุกเอกสารที่ออกจากระบบมี QR สำหรับตรวจสอบความถูกต้องย้อนกลับมาที่ระบบ

### 4.6 อื่นๆ ที่ใช้ร่วมกัน
ค้นหารวม (ข่าว + หนังสือ + เอกสาร + คน + KM), ความเห็น/การกล่าวถึง `@ชื่อ` บนทุกรายการ, ไฟล์แนบ, ส่งออก Excel/PDF, Scoped RBAC, Audit log

## 5. รายละเอียดแต่ละระบบ

### A. สื่อสาร
| ระบบ | ทำอะไร | หมายเหตุ |
|---|---|---|
| **ข่าว/หนังสือเวียน + รับทราบ** | (มีในแผนหลักแล้ว) | |
| **กระดานถาม-ตอบ** | ตั้งกระทู้ตามกลุ่มงาน/หัวข้อ เช่น "ถาม-ตอบการเบิกจ่าย", "ปัญหาโปรแกรม HOSxP", ทำเครื่องหมายคำตอบที่ถูก | ลดคำถามซ้ำในกลุ่ม LINE และกลายเป็นคลังความรู้ |
| **แบบสำรวจ / โหวต** | สำรวจความต้องการอบรม, ความพึงพอใจ, เลือกวันประชุม (โหวตวันที่ว่าง) | ไม่ระบุตัวตนได้ |

> **ไม่แนะนำสร้างระบบแชตเอง** — กลุ่ม LINE ใช้กันแพร่หลายอยู่แล้ว การแข่งด้วยแชตใหม่มักไม่มีคนใช้ เน้นให้ "ความเห็นใต้รายการ" (ใบลา, งาน, หนังสือ) แทน เพื่อให้บทสนทนาผูกกับเรื่องนั้นและค้นย้อนหลังได้

### B. เอกสาร
| ระบบ | ทำอะไร |
|---|---|
| **สารบรรณอิเล็กทรอนิกส์** | ลงทะเบียนรับ (ออกเลขรับอัตโนมัติตามปีปฏิทิน/ทะเบียนแยกหน่วยงาน), สแกน/แนบ PDF, ชั้นความเร็ว/ความลับ, **เกษียนหนังสือ** (ผู้บริหารเขียนสั่งการ → ส่งต่อกลุ่มงาน), มอบหมายผู้รับผิดชอบ, ติดตามสถานะ, ร่างหนังสือส่ง (ออกเลขส่ง), ส่งหนังสือภายในจังหวัด (สสจ. ↔ สสอ. ↔ รพ.สต.) และค้นหาย้อนหลัง |
| **ลงนามอิเล็กทรอนิกส์** | ลงนามหนังสือ/บันทึกข้อความในระบบ (ข้อ 4.5) |
| **คลังเอกสาร & แบบฟอร์ม** | (มีในแผนหลักแล้ว) + โฟลเดอร์ทีม, แชร์ภายในกลุ่มงาน, เวอร์ชัน |
| **ทะเบียนคำสั่ง/ประกาศ** | ออกเลขคำสั่ง สสจ., ค้นหาคำสั่งแต่งตั้งคณะทำงาน, ผูกรายชื่อบุคคลในคำสั่ง → ไปแสดงในประวัติของคนนั้น |

> **ข้อควรตัดสินใจ**: ปัจจุบันมีลิงก์ "สารบรรณ'สาสุข" ซึ่งเป็นระบบภายนอก — ทางเลือกคือ (ก) สร้างสารบรรณของเราเองทั้งระบบ หรือ (ข) ใช้ระบบเดิมสำหรับหนังสือเข้า-ออกนอกหน่วยงาน และทำเฉพาะ **การเดินหนังสือภายใน + เกษียน + ติดตาม** ในระบบเรา *แนะนำ (ข) ก่อน* เพื่อไม่ทำงานซ้ำซ้อนกับระบบระดับกระทรวง แล้วประเมินอีกครั้ง

### C. บุคลากร (HR Self-Service)
| ระบบ | ทำอะไร |
|---|---|
| **ระบบลา** | ยื่นลาทุกประเภทตามระเบียบ (ป่วย, กิจส่วนตัว, พักผ่อน, คลอด, อุปสมบท/ฮัจญ์, ศึกษาต่อ ฯลฯ), **คำนวณวันทำการอัตโนมัติ** (ตัดเสาร์-อาทิตย์และวันหยุดราชการจากปฏิทินวันหยุดที่ HR ตั้งค่า), แสดงวันลาคงเหลือ/สะสม, ยกเลิกลา, ใบรับรองแพทย์แนบเห็นเฉพาะผู้เกี่ยวข้อง, ออกแบบใบลา PDF, รายงานสรุปวันลารายปีงบประมาณสำหรับ HR และการเลื่อนเงินเดือน |
| **ขอไปราชการ/อบรม** | ขออนุมัติเดินทาง (ผูกกับจองรถได้ในคำขอเดียว), ประมาณการค่าใช้จ่าย, **รายงานผลหลังกลับ** (บังคับก่อนขอครั้งถัดไปได้ตามนโยบาย), แนบเกียรติบัตร |
| **ประวัติ & การพัฒนาตนเอง** | ข้อมูลส่วนตัวแก้เองได้ (ผ่าน HR ตรวจ), ประวัติการอบรม/ชั่วโมงพัฒนา, ใบประกอบวิชาชีพ + **เตือนก่อนหมดอายุ** |
| **ทำเนียบ & ผังองค์กร** | ค้นหาคนตามชื่อ/หน่วยงาน/ตำแหน่ง, เบอร์ภายใน, ผังองค์กรสร้างจากต้นไม้หน่วยงานอัตโนมัติ, สถานะ "วันนี้ลา/ไปราชการ" (เพื่อนร่วมงานรู้ว่าติดต่อใครแทน) |
| **ตารางเวร** | จัดเวร (เวรผู้บริหาร, เวร EOC, เวรรักษาการณ์), ขอแลกเวรผ่านการอนุมัติ, แจ้งเตือนก่อนถึงเวร |

### D. ทรัพยากร
| ระบบ | ทำอะไร |
|---|---|
| **จองห้องประชุม** | ดูห้องว่างแบบตาราง, จองพร้อมอุปกรณ์/อาหารว่าง, อนุมัติโดยผู้ดูแลห้อง (ตั้งได้ว่าห้องไหนต้องอนุมัติ), จอที่หน้าห้องแสดงตารางวันนี้ (หน้าเว็บโหมด kiosk) |

| **พัสดุ/ครุภัณฑ์** | ทะเบียนครุภัณฑ์พร้อม **QR ติดเครื่อง** (สแกนดูประวัติ/แจ้งซ่อมได้ทันที), ยืม-คืน, โอนย้ายระหว่างหน่วย, ตรวจนับประจำปีด้วยมือถือ, ค่าเสื่อมราคา |
| **เบิกวัสดุสำนักงาน** | ขอเบิกผ่านแบบฟอร์ม → อนุมัติ → จ่าย, ยอดคงคลัง, เตือนเมื่อต่ำกว่าจุดสั่งซื้อ |

### E. งาน & ประชุม
| ระบบ | ทำอะไร |
|---|---|
| **e-Meeting** | นัดประชุม (ตรวจห้องว่าง + ผู้เข้าร่วมว่าง), วาระและเอกสารประกอบ (อ่านล่วงหน้าบนแท็บเล็ต — ลดกระดาษ), **ลงชื่อเข้าประชุมด้วย QR**, จดรายงานการประชุม, รับรองรายงาน, **มติ → แปลงเป็นงานติดตาม** อัตโนมัติ |
| **สั่งการ-ติดตามงาน** | มอบหมายงานพร้อมกำหนดส่ง (จากเกษียนหนังสือ, มติประชุม หรือสั่งตรง), สถานะ/ความคืบหน้า, กระดาน Kanban ต่อกลุ่มงาน, แดชบอร์ดผู้บริหาร "งานค้าง/เกินกำหนด" |
| **โครงการ & งบประมาณ** | แผนปฏิบัติการประจำปีงบประมาณ, โครงการ → กิจกรรม → งบที่ได้รับ/เบิกจ่ายแล้ว, รายงานผลรายไตรมาส, ข้อมูลส่งออกไปหน้า ITA |
| **รายงานจากหน่วยบริการ** | สสจ. สร้างแบบรายงาน (Form Builder) → ส่งถึง รพ.สต./สสอ. พร้อมกำหนดส่ง → หน่วยบริการกรอกออนไลน์ → ติดตามว่าใครยังไม่ส่ง → รวมผลอัตโนมัติ (แทนการส่ง Excel ทางอีเมล/LINE) → ไหลเข้า Data Hub |

### F. สนับสนุน
| ระบบ | ทำอะไร |
|---|---|
| **แจ้งซ่อม / IT Helpdesk** | แจ้งปัญหา (คอมพิวเตอร์, เครือข่าย, อาคาร) พร้อมรูป, รับเรื่อง-มอบหมายช่าง, สถานะ, ประเมินความพึงพอใจ, สถิติปัญหาที่พบบ่อย |

## 8. ลำดับความสำคัญที่แนะนำ

จัดตาม **คุ้มค่าสูง × ใช้บ่อย × ทำง่าย** — เปิดของที่ทุกคนใช้ทุกสัปดาห์ก่อน เพื่อให้คนเข้าระบบเป็นนิสัย

| ระดับ | ระบบ | เหตุผล |
|---|---|---|
| ⭐⭐⭐ ทำก่อน | แกน Workflow (ระยะ 1), **ระบบลา**, **จองห้องประชุม**, **จองรถ**, **ขอไปราชการ**, หน้างานของฉัน, ปฏิทินรวม, ทำเนียบ | ทุกคนใช้, แทนกระดาษได้ทันที, ปูพื้นแกนกลางให้ระบบอื่น |
| ⭐⭐ ถัดไป | Form Builder, สารบรรณ (เดินหนังสือภายใน + เกษียน), ลงนามอิเล็กทรอนิกส์, e-Meeting, สั่งการ-ติดตามงาน, รายงานจากหน่วยบริการ, แจ้งซ่อม/IT | ผู้บริหารได้ประโยชน์มาก, ลดการตามงานทาง LINE |
| ⭐ ต่อมา | พัสดุ/ครุภัณฑ์, เบิกวัสดุ, โครงการ & งบประมาณ, ตารางเวร, กระดานถาม-ตอบ, แบบสำรวจ, KM, e-Learning | เฉพาะกลุ่มผู้ใช้ หรือต้องเตรียมข้อมูลตั้งต้นมาก |
| ทางเลือก | ผู้ช่วย AI, ลายมือชื่อดิจิทัล PAdES | ต้องการโครงสร้างพื้นฐาน/ใบรับรองเพิ่ม |

## 9. คำถามเพื่อตัดสินใจ

1. **สารบรรณ**: สร้างเองทั้งระบบ หรือทำเฉพาะการเดินหนังสือภายใน + เกษียน + ติดตาม แล้วใช้ระบบสารบรรณเดิมสำหรับหนังสือเข้า-ออกภายนอก (แนะนำแบบหลัง)
2. **ขอบเขตผู้ใช้ระบบภายใน**: เฉพาะเจ้าหน้าที่ สสจ. หรือรวม สสอ./รพ./รพ.สต. ด้วย — โดยเฉพาะระบบลา (รพ. มักมีระบบ HR ของตัวเองอยู่แล้ว)
3. **ระบบที่มีอยู่แล้ว**: HOSOffice ที่ใช้อยู่ครอบคลุมงานลา/จองรถ/พัสดุบ้างหรือไม่ — ถ้าครอบคลุมควรเชื่อมข้อมูลแทนการสร้างซ้ำ
4. **ลงนามอิเล็กทรอนิกส์**: ระดับไหนพอสำหรับการใช้งาน (ระดับทั่วไปพร้อมหลักฐาน หรือต้องใบรับรองดิจิทัล)
5. **ผู้ช่วย AI**: ดูทางเลือกและค่าใช้จ่ายในหัวข้อ 10

## 10. ผู้ช่วย AI — ทางเลือกและค่าใช้จ่าย (ระยะ 4, ไม่บังคับ)

**เสียเงินหรือไม่ — ขึ้นกับวิธี:**

| ทางเลือก | ค่าใช้จ่าย | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **ก. ไม่ใช้ AI** | 0 บาท | ไม่มีความเสี่ยงเพิ่ม | — (ระบบค้นหา Meilisearch ตอบโจทย์ "หาเอกสารเจอ" ได้ส่วนใหญ่แล้ว) |
| **ข. เรียก AI ผ่านคลาวด์ (จ่ายตามใช้)** | ดูตารางด้านล่าง | ไม่ต้องซื้อเครื่อง, เริ่มได้ทันที, คุณภาพสูง | เอกสารถูกส่งออกไปประมวลผลนอกหน่วยงาน, ต้องมีอินเทอร์เน็ตขาออก |
| **ค. ติดตั้งโมเดลบนเครื่องเราเอง** | ลงทุนเครื่อง GPU (ประมาณหลักแสนบาทขึ้นไป — ต้องขอใบเสนอราคาจริง) + ค่าไฟ + คนดูแล; ไม่มีค่าใช้ต่อคำถาม | ข้อมูลไม่ออกนอกหน่วยงาน | ลงทุนก้อนแรกสูง, โมเดลเปิดที่รองรับไทย (เช่น Typhoon, OpenThaiGPT) ความสามารถต่ำกว่าโมเดลคลาวด์ระดับบน |

**ประมาณการทางเลือก ข.** (ตัวอย่างราคาโมเดล Claude ของ Anthropic ณ ต.ค. 2026; ผู้ให้บริการอื่นอยู่ในช่วงใกล้เคียง; ราคาเปลี่ยนได้)
สมมติ 1 คำถาม = ข้อความเข้า ~8,000 token (คำถาม + เอกสารที่ค้นมา) + คำตอบ ~800 token, 1 USD ≈ 35 บาท, ใช้งาน 300 คน × 5 คำถาม/วัน × 22 วัน = 33,000 คำถาม/เดือน

| โมเดล (ราคา USD ต่อ 1 ล้าน token เข้า/ออก) | ต่อคำถาม | ต่อเดือน |
|---|---|---|
| Claude Haiku 5.5 ($0.10 / $0.50) — เพียงพอสำหรับค้นหา/สรุปเอกสาร | ~0.04 บาท | **~1,400 บาท** |
| Claude Sonnet 5.5 ($2 / $10) | ~0.8 บาท | ~28,000 บาท |
| Claude Opus 5.5 ($4 / $20) | ~1.7 บาทขึ้นไป | ~55,000 บาทขึ้นไป |

**คำแนะนำ**
1. ทดลองด้วยทางเลือก ข. + โมเดลเล็ก **เฉพาะเอกสารที่ไม่อ่อนไหว** (หนังสือเวียน, คู่มือ, ระเบียบ) ตั้งเพดานค่าใช้จ่ายรายเดือน — **ห้ามส่งข้อมูลผู้ป่วย/ข้อมูลส่วนบุคคล** และทำบันทึกประเมินผลกระทบ (DPIA) ก่อน
2. วัดผล 2–3 เดือน: มีคนใช้จริงไหม คำตอบถูกต้องไหม (ทุกคำตอบต้องแสดงเอกสารอ้างอิงให้กดตรวจได้)
3. ถ้าใช้มากหรือต้องการใช้กับข้อมูลภายในที่อ่อนไหว → ค่อยลงทุนทางเลือก ค.
4. ในโค้ดทำเป็น adapter (`internal/ai`, interface `Assistant`) — สลับคลาวด์ ↔ เครื่องเราเองได้โดยไม่แก้ระบบอื่น; embedding สำหรับค้นหาตามความหมายรันบน CPU ในเครื่องเราได้เสมอ (ไม่มีค่าใช้จ่ายต่อครั้ง)
